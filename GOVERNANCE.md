# Governance

The repository is currently maintainer-led while the contract is pre-1.0.

- Public issues and pull requests are the decision record.
- Security reports follow [SECURITY.md](SECURITY.md).
- Normative changes require a schema/example update and passing conformance checks.
- Incompatible changes require a new major contract version.
- A publisher-specific requirement is accepted into the core contract only when it can be expressed with domain-neutral semantics and demonstrated by a neutral fixture.
- No implementation or publisher is automatically certified by conforming to this draft.

Before 1.0, the project will document a compatibility window, deprecation policy, release-signing process, and a multi-party review rule for security-critical changes.
