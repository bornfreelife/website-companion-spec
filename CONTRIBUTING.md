# Contributing

This specification is developed in public.

1. Open an issue describing the interoperability, privacy, security, or accessibility problem.
2. Discuss incompatible contract changes before implementing them.
3. Add or update neutral examples and conformance checks with every normative change.
4. Run `npm test` before submitting a pull request.
5. Do not include private publisher data, credentials, signing keys, user progress, or production incident details.

Normative requirements use **MUST**, **MUST NOT**, **SHOULD**, **SHOULD NOT**, and **MAY** in the sense described by RFC 2119 and RFC 8174.
